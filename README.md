# Leopis Digital – Online Store

Static e-commerce site for **Leopis Pvt. Ltd.** (Sri Lanka), hosted on GitHub Pages.
Customers browse products, add to cart, and send the order through **WhatsApp** (cash on delivery, prices in LKR). The site is available in English, Sinhala and Tamil.

## Files

| File | What it does |
|---|---|
| `index.html` | Page structure |
| `style.css` | Design and colours |
| `app.js` | All site logic: products, cart, WhatsApp order, share links, languages, 11.11 Flash Deals, rating line, FAQ |
| `products_final.json` | **The product list the site loads** (name, category, price, image, warranty) |
| `generate_seo_pages.py` | Generates static product/category pages, category links, the featured-campaign page and the sitemap from the current catalog |
| `products/` and `categories/` | Crawlable product and category landing pages generated by `generate_seo_pages.py` |
| `meta_campaign_ids.json` and `featured-products.html` | Fixed 50-product campaign selection and its generated landing page; page prices are read from the current catalog |
| `import_sheet_products.py` | Imports valid `Ready` rows from the Google Sheet |
| `web-product-replacements.xlsx` | Editable Excel control workbook for prices, product photos/details, and stock actions |
| `about.html`, `delivery.html`, `returns-warranty.html`, `contact.html` | Sri Lanka store, delivery, returns/warranty, and support information pages |
| `.github/workflows/import-sheet-products.yml` | Checks the Sheet every 15 minutes, updates SEO pages/sitemap and publishes catalog changes |
| `CNAME` | Custom domain (leopisdigital.com) |

> The site loads `products_final.json`. A file named `products.json` is **not** used.

## Updating products

1. Edit or replace `products_final.json` on GitHub (Add file → Upload files → Replace).
2. Commit and wait about a minute for GitHub Pages to update.
3. Open the site in a private tab (or hard refresh) to see the change.

## Automatic Google Sheet publishing

The repository checks the connected public Google Sheet every 15 minutes. A row is imported only when its `status` is `Ready` and it contains a product number, name, price, category, description, and an individual image URL (or a Google Drive ZIP containing `main_image.jpg`/another supported image). The importer detects image file signatures, extracts the archive's main photo safely, and stores it with the site. The product number is the unique key: an existing number is replaced, and a new number is added. Invalid rows are skipped and reported in the GitHub Action log. The Sheet is read through its public CSV export, so no Google credentials are stored in GitHub.

Use these headers in the Sheet:

```text
Product Image | product rate | product name | product number | description | Warranty | merchants | category | status
```

After a successful import, the website catalog is updated automatically. The importer does not write back to the Sheet; change `Ready` to `Published` manually after confirming the deployment.

### Edit products and remove out-of-stock items with Excel

`web-product-replacements.xlsx` is an editable input, not just an exported report. Edit it and upload/replace that same workbook in the GitHub repository; the workflow also runs when the workbook is pushed to `main`, then checks again every 15 minutes. The workbook has an `Instructions` tab and an `Action` dropdown.

Use the product code and name to identify a row. To change a photo, paste an individual image URL (including a Google Drive file URL) into `if new image`; the workflow downloads it into the website. Optional `New Product Name`, `New Category`, `New Description`, and `New Warranty` cells replace those values when filled. For a price correction, the current site price must match `Published Rate`; the workflow then applies `New Rate`.

To hide an out-of-stock or unwanted product, choose **Out of stock - remove** in `Action`. It is removed from the live catalog and recorded in `removed_product_ids.json`, so scheduled Sheet imports and product rebuilds will not add it back while the action remains selected. To bring it back, use the exact product ID and choose **Restock**; the source Sheet row must still be marked `Ready` for the product to be reimported. Blank/Keep makes no stock change.

Optional Sheet columns are supported for `availability`/`stock`, `brand`, `GTIN`/`barcode`/`EAN`/`UPC`, and `MPN`/manufacturer part number. Use only verified product data. Active catalog listings default to in-stock when no explicit status exists; mark a product `out_of_stock` (or remove/unpublish it) promptly if it cannot be ordered. The current public Sheet has no manufacturer-brand or barcode columns, so those identifiers are intentionally omitted rather than guessed.

## Product sharing

Every product card and product detail view has a **Share product** button. On Android and other supported devices it opens the native share sheet, where the customer can choose WhatsApp, Facebook, Messenger, email or another installed app. Shared product links now use static URLs such as `https://leopisdigital.com/products/example-product--product-code.html`, generated from the product name and code. The older `/?p=PRODUCT_CODE` link continues to open the product detail in the storefront.

## Search pages and sitemap

Run `python generate_seo_pages.py` after changing `products_final.json`. It creates one static page per catalog item, one page per category, crawlable category links on the homepage, and a sitemap containing only indexable product/category pages plus the store information pages. Product offers include feed-backed availability, shipping-policy and return-policy references. The shipping information states the Rs. 450 one-store charge and links to the exact discounted multi-store tiers; no delivery timeframe or blanket return window is invented. Pages with missing or placeholder descriptions are marked `noindex`; health-related product/category pages remain out of the sitemap until catalog claims are reviewed. The 15-minute Sheet publishing workflow runs this generator automatically before committing changes.

The same generator creates `/featured-products.html` from the 50 unique product IDs in `meta_campaign_ids.json`. It uses each product’s current `products_final.json` price without exposing supplier base costs or changing catalog prices. Edit the ID list to rotate campaign picks; the generator verifies that all 50 IDs exist and have indexable product pages. The current selection is a curated advertising shortlist, not a verified best-seller ranking because sales/order analytics are not stored in this repository.

## Merchant references and delivery charges

Every product displays its Store 1–5 reference. The `merchants` column accepts an explicit value such as `merchant 4`; products not matching Merchant 1–4 rules are assigned to Merchant 5. Delivery is calculated by the number of different stores in the cart: 1 store = Rs. 450 (payable Rs. 450); 2 stores = Rs. 900 less Rs. 100 (payable Rs. 800); 3 stores = Rs. 1,350 less Rs. 300 (payable Rs. 1,050); 4 stores = Rs. 1,800 less Rs. 450 (payable Rs. 1,350); 5 stores = Rs. 2,250 less Rs. 800 (payable Rs. 1,450).

The importer recognizes these groups: six-digit product codes in the `100xxx` series are Merchant 1; `P0`/`PO` series codes are Merchant 2; Fochant/Forchant products and products marked `Checking Warranty` are Merchant 3; rows explicitly marked `Merchant 4` are Merchant 4; unmatched products are Merchant 5. A recent-product badge by itself does not change a product's store. The storefront's `category` field remains the product department, not the store number.

## Category organization and product search

The catalog is organized into 23 standard product departments. Legacy Sheet labels such as `Electrical supplies`, `Hardware /`, and `Personal Care / Beauty Gadgets` are mapped to the appropriate existing department during import, so spelling and capitalization variants do not create separate category pages. Product search builds a local index once after catalog load, searches names, product codes, categories and descriptions, ranks stronger matches first, and supports category terms, common synonyms and simple one-character typos. Search, category filters and price sorting work together without sending queries to an external service.

### Product format

```json
{
  "id": "144-EXAMPLE-PRODUCT",
  "name": "Example Product",
  "category": "Kitchen & Dining",
  "price": 1990,
  "base": 1700,
  "image": "https://example.com/photo.webp",
  "description": "Short description",
  "warranty": "Checking Warranty – 3 Days"
}
```

- `id` – product code, shown on the card and in the WhatsApp order. Search finds products by code or name.
- `price` – normal selling price (supplier rate + commission).
- `base` – supplier rate. Only products with `base` take part in the 11.11 Flash Deals. Leave it out to exclude a product.
- `image` – full image link. If it is empty, a placeholder with the product name is shown.
- `warranty` – shown as a green line on the card, in the product popup and in the WhatsApp message. Leave empty to hide it.
- New categories work automatically: just use a new `category` name.

## Commission rule (supplier rate → selling price)

| Supplier rate (LKR) | Commission added (LKR) |
|---|---|
| Under 1,000 | 220 |
| 1,000 – 2,000 | 290 |
| 2,001 – 3,000 | 340 |
| 3,001 – 4,400 | 390 |
| Over 4,400 | 500 |

## 11.11 Flash Deals

Settings are near the top of the flash section in `app.js`:

```js
const FLASH = { end: new Date("2026-11-11T23:59:59+05:30"), factor: 0.5 };
```

- `end` – when the sale stops. After this time prices return to normal automatically, with no upload needed.
- `factor` – share of the normal commission kept during the sale (`0.5` = half, `1` = normal price, `0` = no commission).
- A banner with a countdown and a right-to-left scrolling strip of random flash products appears above the product list.
- Flash cards show the crossed-out normal price and a "Save Rs. X" badge.

## Other settings in `app.js`

- `CONFIG` (top of the file): WhatsApp number, currency, products per page.
- `const SITE_RATING = null;` – the rating line above the products is hidden until it is backed by real customer feedback. Set it to a verified score only when you have supporting reviews.
- `const FAQ = { ... }` – FAQ questions and answers in English, Sinhala and Tamil.
- Scrolling speed of the flash strip: change `55s` in the `.ftrack` style (bigger = slower).

## Uploading tips (GitHub on mobile)

- If GitHub shows **HTTP 400**, open github.com in a private tab and sign in again, or clear GitHub cookies, then retry.
- Upload files to the **main folder** of the repository, not into a subfolder.
- Replace files using the exact same file name.
- Upload in small groups if many files fail at once.
- The old `imgpack_*.json` files (if present) are no longer used and can be deleted.
